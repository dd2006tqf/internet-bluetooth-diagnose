# 简历分点面试辩护技能（coaching-resume-bullets）

> 日期：2026-11-05
> 分类：工作流外实施
> 结果：已完成

## 构思

**要解决的问题**：用户以本仓库为教材准备面试，需要把简历里的一个技术分点练到两种现场都撑得住——面试官不了解这个项目时能讲清楚，面试官技术栈对口时能被连续深挖两三轮。明确约束是**不背代码**，只掌握知识架构与项目全景。

**为什么不做进 OpenSpec change**：本任务只新增 `skills/` 下的文档资产与 `CLAUDE.md` 的一行注册，不改变任何产品行为、接口、构建产物或运行时表面。走 change 流程会引入 fingerprint 与 surface 契约，却没有任何可验证的行为增量，属于形式大于实质。

**备选方案与取舍**：

| 方案 | 取舍 |
| :--- | :--- |
| 讲解版与 drill 拆成两个技能 | 用户须调用两次、自己拼接上下文；已否决 |
| 合并为一个技能、一次输出全部（含 drill 问题+答案） | 一次调用最省事，但用户看到答案后 drill 就失效了；已否决 |
| **合并为一个技能，默认输出 0~6 段后停在第一问（交互式 drill），`--offline` 时一次性给题集** | 采纳。单次调用完成准备，drill 保留真实压力 |

**关键设计决策**：两种面试官不是两套知识，是**同一份骨架的两次投影**。先产出与听众无关的知识骨架，再渲染外行版/行家版——准备两份独立稿子的人，被交叉追问时事实会对不上。

## 实现方式

**新增文件**：

- `skills/coaching-resume-bullets/SKILL.md`（185 行）——主技能。固定八段输出：断言拆解（可主张/需限定/不可主张）、知识骨架（≥3 层、领域通用命名、项目只作锚点）、主线叙事（90s/30s）、双视角渲染、追问树（3 轴 × 3 层）、红线清单、速记卡、drill。附 8 条硬规则与 6 条反模式。
- `references/depth-axis.md`（98 行）——三条追问轴（机制/取舍/证据）各三层，含选轴启发式、drill 分支与升层规则、通用变体清单（规模/环境/故障/时间/相反条件）。
- `references/rendering-guide.md`（99 行）——外行版与行家版的结构、写法规则、正反例、7 条对照自检、英文开场句。

**修改文件**：

- `CLAUDE.md`——在「协作」技能清单 `code-explainer` 之后登记本技能。

**验证手段**：用两个子代理做 RED/GREEN 对照，不碰产品代码。

- RED（无技能，直接给同一条 eBPF 分点）：产出「代码逐行讲解的墙」，并且**虚构了项目事实**——声称 HTTP 延迟探针用 uprobe 挂用户态库、核心聚合用 per-CPU map、增量上报主路径走 ringbuf、计数发生在设备层。四项均经 `grep` 证伪：仓库内 `.bpf.c` 无任何 uprobe；流量与进程统计走 `LRU_HASH`；ringbuf 仅用于 `bt_events`；计数点是 `ip_queue_xmit` / `udp_sendmsg`（套接字/IP 层）。
- GREEN（加载技能）：八段结构齐全，drill 只问第一问即停；把「兼容多内核版本」判为不可主张（换内核需重新生成 `vmlinux.h`，`docs/交叉编译与开发板部署.md:577` 有明文）、把「低开销」判为需限定。

## 结果

技能已落地并通过 RED/GREEN 对照。RED 的虚构恰好证明技能的「证据核对前置」不是形式主义——那条 uprobe 说法如果被用户背进面试，是一场无法挽回的减分。

**顺带发现的仓库缺陷（未修，需用户决策）**：仓库内对 eBPF 探针数量的表述不一致，实测 `.bpf.c` 文件为 **12** 个：

| 出处 | 表述 |
| :--- | :--- |
| `README.md:124` | 12 个 eBPF 探针 |
| `docs/交叉编译与开发板部署.md:9` / `:76` | 11 个 eBPF 探针 |
| `弱网项目简历知识库.md:842` | 10 个独立 `.bpf.c` 源码 |
| `弱网项目简历知识库.md:1019` | 11 个 eBPF 探针字节码 |

技能已把「不报精确探针数量」写入红线，但**知识库本身仍需订正**，否则用户会从源头读到错误数字。

**另一处口径核对**：「低开销」目前只有间接证据——`tools/soak_monitor.py` 会采样 `cpu_percent`，但 `tools/analyze_soak.py` 的冻结判据（RSS/FD/DB 增长、句柄波动、emitter 失败率等）**不含 CPU 项**，也没有有/无探针的 A/B 对照。对外只能讲「长稳期有 CPU 采样、未见异常」，不能讲「开销低」。

**是否升格为正式 change**：不需要。文档资产无行为表面。
