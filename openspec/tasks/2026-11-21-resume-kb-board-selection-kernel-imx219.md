# 简历知识库扩充：开发板选型论证 + 内核重编译 + IMX219/V4L2 调试全记录

> 日期：2026-11-21
> 分类：工作流外实施（文档）
> 结果：完成

## 构思

用户要在 `弱网项目简历知识库.md` 中补充三块内容：

1. **明确 Radxa Cubie A7A 的板卡配置与 SoC 信息**，并结合项目背景说明选型理由：
   性能匹配、性价比（相比 RK 等板卡）。
2. **内核重编译的记录汇总**——用户特别强调 `-99btf1` 内核本身就是重编译产物，
   当时改的是 BTF 的一个配置项，这是 eBPF 能力的起点。
3. **IMX219 / V4L2 调试过程汇总**，供用户重温。

知识库原有附录二第 1 节已有一版硬件参数表，但存在三处与实测不符：

- 内核写的是 `-99btf1`，实际早已是 `-100btf1amp`（第二次重编译）；
- 存储写成「128 GB eMMC / NVMe」，实测 `/dev/sda` 总线路径是 `4520000.ufs/host0`；
- 内核 BTF 被表述为「具备关键内核特性：预置内核 BTF」，暗示是板厂提供——
  实际是**自己重编译打开的**，出厂内核 `# CONFIG_DEBUG_INFO is not set`。

第 3 条是最关键的错误：它把项目最有分量的一项工作（重编译内核打开 BTF）
说成了「板子本来就有」，等于把技术亮点抹掉了。

## 实现方式

### 一、先取证，不改文档

全部结论都先落到板端实测或仓库记录，不依赖记忆：

| 取证项 | 手段 | 结果 |
| :--- | :--- | :--- |
| SoC / 板卡型号 | `cat /proc/device-tree/compatible` | `radxa,cubie-a7a` / `arm,sun60iw2p1` / `allwinner,sun60i-a733` |
| CPU 拓扑 | 逐核读 `midr_el1` + `cpu_capacity` | cpu0-5=`0xd05`/385，cpu6-7=`0xd0b`/1024 |
| 存储介质 | `readlink -f /sys/block/sda` | `.../4520000.ufs/host0/...` ⇒ **UFS**，不是 eMMC/NVMe |
| 内核版本 | `uname -a` | `5.15.147-100btf1amp-a733` |
| BTF 现状 | `ls /sys/kernel/btf/` + `bpftool prog list` | 4.4 MB / 74 条 / **51 个程序在跑** |
| SoC 规格 | Radxa 官方产品页（WebFetch） | A76×2+A55×6、GPU BXM-4-64、NPU 3 TOPS、VPU 4K、LPDDR5、UFS |
| 价格锚点 | Radxa 官方产品页（WebFetch） | 2 GB 版 **$25 起**；官方自称同类半价 |

### 三、几个刻意保留的「不能说」

- **不编具体价格**：8 GB 版官方未公开标价，只写「2 GB 版 $25 起」与官方自称同类半价，
  并标明是官方宣称而非第三方实测。
- **不宣称性能超越 RK3588**：RK3588 是 4×A76+4×A55，事实更强；
  论证落在「本项目瓶颈不在算力，在能力门槛」。
- **不宣称做过 RK 对标**：对比表是按公开规格 + 项目自身负载做的推理。
- **明确 NPU 未落地**：只做过可行性分析，实际用的是 VPU 硬件编码。
- **明确内存颗粒型号非板端实测**：容量实测，LPDDR5 来自官方规格。
