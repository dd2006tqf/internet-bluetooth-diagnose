# Qt 看板整页滚动（1024x600 小屏可用 + 手指划动）

> 日期：2026-11-13（2026-11-14 板端复验并修正默认尺寸逻辑）
> 分类：工作流外实施
> 结果：已完成（x86 100/100 用例通过；ARM64 交叉编译通过；板端真机复验通过——渲染无回归、空态无滚动条、数据态 57px 滚动条为已知形态）

## 构思

### 问题

看板原布局的 `minimumSizeHint().height()` 实测 **661px**。现场最便宜、
最容易买到的 7 寸触摸屏是 **1024x600**——差 61px。这个差距不是调整一下
间距就能消掉的：`resize(1024,600)` 会被 Qt 弹回 661，底栏（诊断行、建议动作）
直接被裁掉，而那几行恰恰是产品定位里「把数据变成结论」的部分。

两条路：

| 方案 | 做法 | 否决理由 |
| --- | --- | --- |
| 压缩内容 | 缩字号、砍底栏行数，把内容压进 600 | 底栏承载的是结论不是装饰，删了就只剩一堆数字；而且每加一行信息都要重新打一次这场仗 |
| **整页滚动（采纳）** | 整页包进 `QScrollArea`，小屏划一下看完整内容 | 信息一条不少；代价是小屏上底部内容需要一次滑动才可见 |

选整页滚动。**关键不在「能滚」，在于「空态下桌面端不该滚」**——滚动是给小屏
兜底的，默认窗口一打开就常驻一条滚动条会显得布局没排好。

> 2026-11-14 板端复验后的修正：上面这句原本写的是「桌面端不该滚」，实测证明
> **只对空态成立**。真实数据到达后内容从 674px 涨到 770px，默认 720 窗口必然
> 出现 57px 可滚范围。这不是布局没排好，是内容真的有那么多。详见「验证手段」。

### 为什么不做成 OpenSpec change

用户既定要求（memory `no-new-openspec-change-by-default`）：除非明确点名，
不新开 change。本改动是既有 UI 内部布局调整，无新增产品表面、无新增配置键、
无新增 entrypoint。按 CLAUDE.md 在 `openspec/tasks/` 留记录，**不具备验收效力**。

### 关键决策

1. **默认高度由内容推导（2026-11-14 修正）。** 最初写的是固定 `resize(1024, 720)`，
   理由是「内容 + 状态栏正好凑满 720」。这个理由只在当时的主题/字体组合下成立，
   是一个巧合而不是契约。改成在 `build_ui()` 末尾按
   `scroll->widget()->sizeHint().height() + statusBar()->sizeHint().height()` 反推，
   下限仍取 720（720p 屏的基准分辨率，内容更矮时不该缩成小窗）。
   坑：取 `centralWidget()->sizeHint()` 是错的——那是 `QScrollArea` 自身，与内容无关。

2. **`setWidgetResizable(true)` 必开。** 让内容宽度恒等于视口宽度（不产生横向滚动），
   高度取内容自身 `sizeHint`：比视口高就滚，比视口矮就撑满。关掉的话内容按原始尺寸
   显示，宽屏两侧各留一条空白。

3. **横向永久关闭（`ScrollBarAlwaysOff`）。** 看板是竖排一列，横向本无溢出；
   留着横条只会在触摸时误触发左右晃，还白占 14px 高度。

4. **手势用 `TouchGesture` 而非 `LeftMouseButtonGesture`。** 后者会把「点按钮」和
   「拖页面」混成同一件事：按下按钮后手指一动就变成拖页面，按钮永远点不动。
   `TouchGesture` 只吃触摸事件，鼠标点击与按钮行为完全不受影响。

5. **手势必须抓在 `viewport` 上，不是 `QScrollArea` 本身。** 内容 widget 盖在滚动区
   之上，触摸事件落不到滚动区本体。抓错对象的表现是「滚动条能拖、手指划不动」——
   现场没有键盘鼠标时就是死界面。这条单独写了一个测试守住。

6. **滚动条不做成 40px 触控目标。** 推荐的 40px 会吃掉本就不多的横向空间。
   定位是「还有更多内容」的视觉提示，主交互是划屏，所以 10px 细条 + 高对比滑块。

### 验证手段

**x86 offscreen（100 用例 / 5 套件全绿，0.82s）**

```
dashboard_data      55 通过
chart_geometry      12 通过
line_chart_widget   12 通过
theme                9 通过
main_window         12 通过  ← 原 9 + 新增 3
```

**布局数字实测**（一次性探针，跑完已删，不进仓库）

⚠️ 这里踩过一个坑：**必须先 `apply_theme()` 再测**。主题的 QSS 会改字号，
未应用主题时内容高 690、应用后 674，两者差 16px，用错基准会把「默认够不够放」
判反。以下全部是**应用主题后**的数字。

x86（QT 5.15.13，offscreen）：

| 窗口高 | 视口高 | 内容高（空态） | 纵向可滚范围 |
|--------|--------|----------------|--------------|
| 720（默认） | 693 | 674 | 0 |
| 700 | 673 | 674 | 1 |
| 600 | 573 | 674 | **101 px** |
| 480 | 453 | 674 | **221 px** |

`minimumSizeHint().height()` = **93 px**（应用主题后；原 661），
`resize(1024,600)` 不再被弹回。`chrome`（窗口高 − 视口高）恒为 **27–28 px**
（即状态栏高度），600/700/720/740/760/800 六个高度逐一验证过。

**板端（ARM64，真机，Qt 5.15.2）实测**——这一轮才暴露关键事实：

```
空态         content=674  window=720  viewport=693  scroll_max=0
真实数据 9s  content=770  window=720  viewport=693  scroll_max=57
```

**「默认窗口不出现滚动条」只在空态成立。** 真实数据到达后，那几个
「有数据才 show()」的行（警告行、人读摘要、次要问题计数）撑开内容，
默认 720 窗口出现 57px 可滚范围。这是内容量决定的，不是布局缺陷：

- 要消掉滚动条，只能砍掉底栏信息（违背「把数据变成结论」的定位）
  或把默认高度提到 800（超出 720p 屏）。
- 整页滚动的意义正在于此：内容比屏高时可以划，而不是被裁。

**ARM64 交叉编译**：`build-qt-arm64/weaknet_dashboard` 518800 B，
最高 glibc 需求 `GLIBC_2.17`（板端 2.31），`strings` 确认 `QScrollArea` 已链入。

**板端渲染无回归**（真实数据 offscreen 截图 1024×720）：背景主色
`(245,246,248)` 占 56%、白卡片 14599 采样点、GOOD 绿 `#2E7D32` 2011px、
底栏白色区域正常铺满。

**未做**：划屏手感（惯性曲线、跟手程度）。单测只断言「手势抓在 viewport 上」，
不假装覆盖手感——板端当前无触摸屏硬件。

## 结果

### 已达成的

- 1024x600 从「底栏被裁」变成「划一下可见」，信息零删减。
- **空态**下默认 1024x720 无滚动条；**真实数据下会滚 57px**——见上节实测。
  这个区别必须分开说：把「空态不滚」当成「运行时不滚」是错的。
- 三条新测试各自守一个独立失败模式，不是重复断言：
  - `WholePageIsInsideAScrollArea`：整页可滚 + 最小高度 ≤600 + 真能滚到底部内容
    （断 `visibleRegion()` 非空，只断「有可滚范围」不够——范围存在但内容没被覆盖时照样滚不出东西）
  - `DefaultSizeFitsWithoutScrollBar`：默认尺寸与内容高度**保持关系**，不断言魔数 690
    （否则正当排版调整也过不去）
  - `FingerSwipeGestureIsGrabbedOnViewport`：抓对对象，含反向断言
    `EXPECT_FALSE(QScroller::hasScroller(scroll))`

### 遗留

1. **数据态滚动条是已知形态，不是缺陷**。真实数据下 770px 内容装不进 720px 屏，
   出现 57px 可滚范围。要消掉它只能砍信息或超 720p，两条都不可接受，所以接受滚动。
   如果将来现场反馈「桌面端滚动条碍眼」，正确做法是让默认高度跟着数据态长高
   （在数据到达后 resize），而不是把底栏删短——但那样窗口会超出 720p 屏高。
2. **`content = 674px` 是一处隐性耦合**：调大字号或间距会顶破 693 的视口，
   届时 `DefaultSizeFitsWithoutScrollBar` 会先失败。默认高度已改为按内容推导
   （`content_hint + statusBar`，下限 720），所以内容涨了窗口会跟着长，
   这条测试守的是「推导逻辑没被破坏」。
3. **10px 滚动条在纯鼠标环境不好点**。当前定位是触摸现场，桌面以滚轮为主，
   可接受；若将来桌面端成为主场景，应加宽或改 `QScrollBar` 策略。
4. **手势与图表交互可能冲突**：`LineChartWidget` 若将来加拖拽/缩放，需重新评估
   `TouchGesture` 是否会被抢走。
