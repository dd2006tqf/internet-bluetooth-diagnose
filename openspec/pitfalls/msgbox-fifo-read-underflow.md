# sunxi msgbox：读空 FIFO 会让 `MSG_ST` 从 0 下溢成 15

> 发现于：2026-11-18
> 位置：`drivers/msgbox/sunxi-msgbox.c`、A733（sun60iw2）msgbox 寄存器
> 影响：把「队列为空」误读成「有 15 条消息堆积」，进而得出完全错误的结论

## 现象

用内核模块或 `/sys/class/sunxi_dump` 读 msgbox 的 `MSG_ST`（消息计数寄存器）
再读 `MSG_FIFO`（取数据）时，出现了自相矛盾的结果：

```text
LOCAL p=0 msg_st=0x0000000f      ← 看起来有 15 条消息
读 0x03004070（p0 FIFO）得到 0x00000000
再读 msg_st 还是 0x0000000f      ← 读不走？消息数不下降？
```

更诡异的是**每次读都会让计数在 0 和 15 之间来回跳**：

```text
UNDERFLOW loc p=0 before=0 read=0x00000000 after=15
UNDERFLOW loc p=1 before=0 read=0x00000000 after=15
UNDERFLOW loc p=2 before=0 read=0x00000000 after=15
```

`before=0` 却读出数据，读完变 `after=15`。

## 成因

**`MSG_ST[3:0]` 是一个 4 位环形计数器，读空 FIFO 会下溢回绕：**

```
0 - 1 = 15   (4-bit wrap)
```

也就是说：

- 队列里**没有**消息时，`MSG_ST = 0`
- 如果此时仍然执行一次 `readl(MSG_FIFO)`，硬件把计数减一
- `0 - 1` 在 4 位里回绕成 `15`

于是你看到 `15`，以为有 15 条消息；再读一次变成 `14`，一路递减到 `0`，
再读一次又回到 `15`。**永远不会报错，永远不会卡住，看起来像"有消息"**。

正确行为应该是「FIFO 空时读操作应当无副作用」，但这个硬件不是。

## 为什么极其危险

这个假象**完美模拟了「有 15 条消息堆积」**：

| 假象 | 天真解读 | 真相 |
| --- | --- | --- |
| `MSG_ST = 15` | 对方发了 15 条 | 我读空队列读出来的 |
| 逐次读递减到 0 | 消息被消费完了 | 我把计数器读着玩回了 0 |
| 再读又变 15 | 对方又发了 | 又下溢了一次 |

**任何"先读状态、再读数据"的轮询循环都会自己制造出"有数据"的假象。**

## 修法

**读之前必须先检查计数，读完必须重新验证计数变化符合预期。**

```c
/* 正确：只在有数据时读 */
if ((readl(base + MSG_ST(n, p)) & MSG_NUM_MASK) > 0)
        v = readl(base + MSG_FIFO(n, p));
```

**绝不要**写成下面这样（无保护地探测 FIFO）：

```c
v = readl(base + MSG_FIFO(n, p));   /* 空队列也会读，计数器下溢 */
if (v) ...                          /* 拿到的是上次残留的旧值 */
```

**判断"是否真的收到过消息"的正确方式**：

1. **把队列读到计数为 0 后，停止读**，然后静置观察计数是否自己涨起来；
2. 计数**自己**从 0 涨到非 0，才是真消息；
3. 读操作本身**绝不能**贡献计数。

上游驱动 `sunxi_msgbox_read_handler()` 有 `while (sunxi_msgbox_peek_data(chan) && ...)`
保护，也就是**先 peek（读 `MSG_ST`）再 read（读 `MSG_FIFO`）**，所以正常路径不会触发。
只有绕过驱动直接裸读寄存器时才会踩到。

## 本次踩坑过程

1. 用 `sunxi_dump` 读 `MSG_ST` 看到 `0x0f`，判定「E902 发了 15 条消息给 A 核」
2. 读 FIFO 拿到 `0x00000000`，又判定「消息内容全是 0，可能是心跳」
3. 直到用探针模块做了 **before / read / after** 三段记录，才看到
   `before=0` → `read` → `after=15` 这个铁证
4. 改正后重做只读快照（全程不碰 `MSG_FIFO`），得到
   `MSG_ST` 全为 0 的干净结果

## 教训

**「状态寄存器」不等于「可信的观测」。**
有些硬件把「计数」实现成可回绕的环形游标，非法操作（空读）会让它回绕，
而且**回绕后的值恰好落在合法范围内**，肉眼无法与真实数据区分。

判据必须是**双向的**：

- 队列空 → 计数必须稳定在 0，且**静置不自增**
- 队列非空 → 读一次，计数必须恰好减 1

只看到「计数非 0」不足以断言有消息，必须排除「自己的读操作造成的」。
