# 全黑帧先查镜头遮挡，别先怀疑驱动

> 发现于：2026-11-11
> 位置：板端实测（IMX219 + sunxi-vin），与代码无关
> 影响：把「镜头保护膜没撕」误判为 sensor/ISP 故障，会去查一整条本来正常的链路

## 现象

采集打通、`rc=0`、帧数正常、`seq_gaps=0`，但导出的每一帧都是纯黑。
像素统计：

```text
mean=0.7   max=60   nz>16=0.1%   帧间差 0.5~0.9
```

`nz>16=0.1%`（超过 16 的像素占比千分之一）与帧间差 0.5~0.9（噪声级）
都在说「这不是完全死掉的 0，而是有微弱噪声的黑」。
这种「有一点点噪声的黑」特别容易让人往「sensor 上电了但没出图 / ISP 没启动 /
pixel format 解释错了」方向查。

撕掉镜头保护膜后：

```text
mean=11.8  max=252  nz>16=11.0%  帧间差 1.8~9.9
```

画面正常（仍偏暗是环境照度低，用户已确认）。

## 成因

IMX219 模组出厂时镜头前贴一层保护膜，不透明。sensor 完全正常工作、
ISP 完全正常工作、DMA 完全正常工作——**光没进来**。

判据是 `max`：

| | `max` | 含义 |
| --- | --- | --- |
| 撕膜前 | **60** | 暗电流 + 读出噪声的天花板 |
| 撕膜后 | **252** | 真实场景有高光 |

`max` 是最能区分「全黑」与「极暗」的单一指标：`mean` 会被大面积黑背景拉低，
`nz>16` 依赖阈值选取，而 `max` 只问一个问题——**这一帧里最亮的像素有多亮**。
全黑时它被噪声限制在两位数；有光时它立刻接近饱和。

`mean=0.7` 配 `max=60` 这个组合本身就是证据：如果是格式解读错误（比如把
RAW10 当 NV12 读），`max` 会顶到 255 而不是停在 60。

## 修法

**全黑的第一步是摘下镜头看有没有遮挡，不是读代码。**

```bash
# 判据：max 是两位数还是接近 255
ssh board 'v4l2-ctl -d /dev/video0 --set-fmt-video=width=1640,height=1232,pixelformat=NV12 \
  --stream-mmap --stream-count=1 --stream-to=/tmp/f.raw'
```

然后看该帧的 `max`。两位数 → 先查物理遮挡；接近饱和 → 再查格式与 ISP。

## 边界

- **`max` 低也可能是环境真的极暗。** 本次撕膜后 `mean` 只有 11.8，
  画面依然偏暗，是用户环境照度低。所以判据不是「够不够亮」，
  而是「`max` 有没有超过噪声天花板」。
- 长曝光下暗电流会让 `max` 抬高，此时两位数可能不是遮挡。所以要在
  **默认曝光**下测。
- 这条只覆盖「镜头被挡」。若 sensor 根本没上电，`max` 会是恒定的 0
  且帧间差为 0（完全没有噪声），那是另一个判据。

## 教训

**物理层的问题不会在软件层留下符合软件预期的痕迹。**

本次的正确排查顺序应该是：`max` 是多少 → 两位数 → 摘镜头看一眼。
实际顺序是：查格式 → 查 ISP → 查 DMA → 最后才想到物理遮挡。
成本差距以小时计，而正确答案一直在手边。

判断「全黑」时，`max` 比 `mean` 有信息量：**`mean` 说平均有多暗，`max` 说有没有光。**
