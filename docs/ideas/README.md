# 💡 Ideas — 功能设想与技术草案

这个文件夹用于存放 **尚未正式启动工作流的功能设想和技术草案**。

## 定位

`docs/ideas/` 是个人灵感记录区，区别于 `openspec/` 下的正式变更管理流程：

| | `docs/ideas/` | `openspec/` |
|---|---|---|
| 阶段 | 想法孵化 | 正式规划 |
| 格式 | 自由，记录方便即可 | OpenSpec 标准格式 |
| 约束 | 无工作流约束 | 受 harness 铁律约束 |
| 产出 | 最终可能升级为 OpenSpec proposal | 直接驱动实现 |

## 文档结构建议

每个想法建议包含以下部分（可自由增减）：

```markdown
# 功能名称

## 一句话摘要
这个功能是什么。

## 动机/痛点
为什么想做这个。

## 初步技术方案
大致怎么做。

## 涉及的模块
影响哪些组件。

## 优先级/状态
- [ ] 待评估 / 进行中 / 已搁置 / 已实现

## 参考资料
灵感来源、相关链接。
```

## 工作流衔接

当一个想法准备正式启动时：
1. 从本目录的草案中提炼需求
2. 创建 OpenSpec change（`scripts/change_new.sh <name> --switch`）
3. 按照正式工作流推进（proposal → design → tasks → implementation → evaluation）

**注意：** 本目录下的文档不受 OpenSpec 工作流铁律约束，可以自由编辑。
