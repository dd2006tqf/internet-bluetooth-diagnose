# 交叉编译与开发板部署指南

## 一、概述

本文档描述如何将 WeakNet 网络诊断系统从 x86_64 开发机交叉编译到 ARM64 开发板（Radxa Cubie A7A），并建立高效的日常开发循环。

### 核心思路

> **电脑编辑源码 → 常驻 ARM64 构建容器做增量编译 → `rsync` 只同步变化的产物 → 开发板运行测试。**

相比传统的"全量编译 + 整包 scp"方式，本方案将日常操作压缩为一条命令：

```bash
./tools/ci.sh
```

### 方案优势

| 传统方式 | 本方案 |
|----------|--------|
| 每次重建 Docker 镜像 | 镜像只构建一次 |
| `make clean` 全量编译 | 增量编译，只重编变化文件 |
| 重新打 tar 包 | 直接整理部署目录 |
| 每次手动 scp 整包 | `rsync` 只传差异文件 |
| 重新生成 vmlinux.h | 预置开发板 vmlinux.h |

## 二、架构与原理

### 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│  开发机 (x86_64 CentOS Stream 10)                           │
│                                                             │
│  ┌─────────────┐    bind mount     ┌──────────────────┐    │
│  │  源码编辑    │ ───────────────→ │ weaknet-arm64-dev│    │
│  │  (IDE/vim)  │   /home/.../src   │ (常驻ARM64容器)   │    │
│  └─────────────┘                   │                  │    │
│                                    │ • 增量 make -j1  │    │
│                                    │ • 生成 dist-arm64│    │
│                                    └────────┬─────────┘    │
│                                             │              │
│                                             │ rsync 增量   │
└─────────────────────────────────────────────┼──────────────┘
                                              │
                                              ↓
┌─────────────────────────────────────────────────────────────┐
│  开发板 (ARM64 Radxa Cubie A7A)                             │
│  /home/radxa/weaknet/                                       │
│  ├── server/bin/weaknet-dbus-server                         │
│  ├── server/build/*.bpf.o                                   │
│  ├── client/bin/test-client                                 │
│  ├── client/lib/libweaknet.so                                         │
│  └── lib/libbpf.so*                                         │
│                                                             │
│  weaknet-test-full.sh  ← SSH 远程执行                             │
└─────────────────────────────────────────────────────────────┘
```

### 关键设计

| 设计 | 作用 |
|------|------|
| **bind mount 源码** | 电脑改源码，容器立即看到，无需复制源码 |
| **常驻容器** | 避免每次 `docker run` 开销，保留编译缓存 |
| **不 make clean** | 只重编变化文件，实现增量编译 |
| **rsync --delete** | 只传差异文件，自动清理开发板多余文件 |
| **vmlinux.h 预置** | 从 board-assets 复制，不依赖容器内生成 |
| **dbus-run-session** | 开发板无需系统 D-Bus 服务，私有会话即可测试 |

### 构建产物映射（CMake，推荐）

| 构建命令 | 产物 | 路径 |
|----------|------|------|
| `cmake --build build-arm64 -j1` | 服务端可执行文件 | `build-arm64/server/weaknet-dbus-server` |
| `cmake --build build-arm64 -j1` | 历史查询工具 | `build-arm64/server/history_query_tool` |
| `cmake --build build-arm64 --target ebpf -j1` | ARM64 eBPF 程序 | `build-arm64/server/build/*.bpf.o` |
| `cmake --build build-x86 --target weaknet` | x86 客户端动态库 | `build-x86/client/lib/libweaknet.so` |
| `cmake --build build-arm64 --target weaknet` | ARM64 客户端动态库 | `build-arm64/client/lib/libweaknet.so` |
| `cmake --build build-arm64 --target test_client_bin` | ARM64 客户端测试程序 | `build-arm64/client/bin/test_client_bin` |

> **注意**：ARM64 构建统一使用 CMake，构建缓存位于 `build-arm64/`；x86 本地验证使用独立的 `build-x86/`。 |

> **⚠️ 重要**：编译必须使用 `-j1`，不能使用更高的并行度。QEMU ARM64 模拟下高并行度会导致编译器崩溃（segfault）。ccache 已安装在容器中，可显著加速增量编译。

## 四、一次性配置

以下步骤只需执行一次，配置完成后长期有效。

### 4.1 构建 ARM64 镜像

镜像基于 Debian 11，包含交叉编译所需的全套工具链和 libbpf v1.3.0。

Dockerfile 位于 [.docker/arm64-builder/Dockerfile](file:///home/tanqf/AI-powered-Network-Diagnostics/.docker/arm64-builder/Dockerfile)。

```bash
cd ~/AI-powered-Network-Diagnostics

# 构建 ARM64 镜像（使用 QEMU 模拟，首次较慢）
docker build \
    --platform linux/arm64 \
    -f .docker/arm64-builder/Dockerfile \
    -t weaknet-builder:bullseye-arm64 \
    .
```

验证镜像：

```bash
docker images weaknet-builder:bullseye-arm64
# 预期: weaknet-builder  bullseye-arm64  ...  963MB

docker run --rm --platform linux/arm64 weaknet-builder:bullseye-arm64 uname -m
# 预期: aarch64
```

> **说明**：此步骤已完成，镜像 `weaknet-builder:bullseye-arm64`（963MB）已存在。除非修改 Dockerfile 或依赖版本，否则无需重新构建。

### 4.2 准备开发板 vmlinux.h

eBPF 程序编译需要目标内核的 BTF 类型信息。开发板的内核与开发机不同，必须使用开发板的 `vmlinux.h`。

```bash
# 1. 在开发板上生成 vmlinux.h
ssh radxa@192.168.2.77 \
    'bpftool btf dump file /sys/kernel/btf/vmlinux format c' \
    > board-assets/vmlinux.h

# 2. 验证文件
ls -lh board-assets/vmlinux.h
# 预期: 约 2.4MB

head -5 board-assets/vmlinux.h
# 预期: #ifndef __VMLINUX_H__
#       #define __VMLINUX_H__
```

> **说明**：此步骤已完成，[board-assets/vmlinux.h](file:///home/tanqf/AI-powered-Network-Diagnostics/board-assets/vmlinux.h)（2.4MB）已就位。除非开发板内核发生变化，否则无需重新生成。

### 4.3 创建常驻构建容器

创建一个长期运行的 ARM64 容器，通过 bind mount 共享源码目录。

```bash
cd ~/AI-powered-Network-Diagnostics

# 删除可能存在的旧容器
docker rm -f weaknet-arm64-dev 2>/dev/null || true

# 创建常驻容器
docker run -d \
    --name weaknet-arm64-dev \
    --platform linux/arm64 \
    --user "$(id -u):$(id -g)" \
    -e HOME=/tmp \
    -v "$PWD":/src:Z \
    -w /src \
    weaknet-builder:bullseye-arm64 \
    sleep infinity
```

参数说明：

| 参数 | 作用 |
|------|------|
| `--platform linux/arm64` | 以 ARM64 架构运行（QEMU 模拟） |
| `--user $(id -u):$(id -g)` | 使用当前用户身份，避免文件权限问题 |
| `-e HOME=/tmp` | 设置 HOME 目录（避免权限警告） |
| `-v "$PWD":/src:Z` | bind mount 源码目录，`:Z` 处理 SELinux 标签 |
| `-w /src` | 设置工作目录 |
| `sleep infinity` | 保持容器常驻运行 |

验证容器：

```bash
# 检查容器状态
docker ps --filter name=weaknet-arm64-dev
# 预期: STATUS = Up ...

# 验证架构
docker exec weaknet-arm64-dev uname -m
# 预期: aarch64

# 验证源码可见
docker exec weaknet-arm64-dev ls /src/server/Makefile
# 预期: /src/server/Makefile
```

### 4.4 创建一键部署脚本

在开发机创建增量编译与部署脚本。

```bash
cd ~/AI-powered-Network-Diagnostics
mkdir -p tools
```

创建 [tools/ci.sh](file:///home/tanqf/AI-powered-Network-Diagnostic./tools/ci.sh)：

```bash
#!/usr/bin/env bash
set -euo pipefail

# ============================================================================
# WeakNet 增量编译与部署脚本
# 用法: ./tools/ci.sh
# 环境:
#   CONTAINER - 构建容器名 (默认: weaknet-arm64-dev)
#   BOARD     - 开发板 SSH 地址 (默认: radxa@192.168.2.77)
#   JOBS      - 编译并行度 (默认: 2)
# ============================================================================

CONTAINER="${CONTAINER:-weaknet-arm64-dev}"
BOARD="${BOARD:-radxa@192.168.2.77}"
JOBS="${JOBS:-2}"

ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
cd "$ROOT"

echo "===== 检查构建容器 ====="

if ! docker inspect "$CONTAINER" >/dev/null 2>&1; then
    echo "错误: 容器 $CONTAINER 不存在"
    echo "请先按文档创建常驻 ARM64 构建容器"
    exit 1
fi

if [ "$(docker inspect -f '{{.State.Running}}' "$CONTAINER")" != "true" ]; then
    echo "启动容器 $CONTAINER ..."
    docker start "$CONTAINER" >/dev/null
fi

echo "===== ARM64 增量编译 (cmake) ====="

docker exec "$CONTAINER" bash -lc "
set -euo pipefail
cd /src

# CMake 增量编译（自动发现源文件，无需手动维护列表）
echo '--- CMake 配置 + 编译 ---'
cmake -B build-arm64 -DCMAKE_BUILD_TYPE=Debug 2>&1 | tail -3
cmake --build build-arm64 -j1 2>&1 | tail -5

echo '===== 生成部署目录 ====='

rm -rf dist-arm64

mkdir -p \
    dist-arm64/server/bin \
    dist-arm64/server/build \
    dist-arm64/server/logs/server \
    dist-arm64/client/bin \
    dist-arm64/client/lib \
    dist-arm64/lib

# 服务端
install -m 0755 \
    build-arm64/server/weaknet-dbus-server \
    dist-arm64/server/bin/weaknet-dbus-server

install -m 0755 \
    build-arm64/server/history_query_tool \
    dist-arm64/server/bin/history_query_tool

# BPF 程序
for f in build-arm64/server/build/*.bpf.o; do
    install -m 0644 "$f" dist-arm64/server/build/ 2>/dev/null || true
done

# 客户端
install -m 0755 \
    build-arm64/client/bin/test_client_bin \
    dist-arm64/client/bin/test-client

install -m 0644 \
    build-arm64/client/lib/libweaknet.so \
    dist-arm64/client/lib/libweaknet.so

# libbpf 运行时依赖（开发板可能未安装 libbpf 1.3.0）
cp -a /usr/local/lib/libbpf.so* dist-arm64/lib/

echo '===== 架构检查 ====='

file \
    dist-arm64/server/bin/weaknet-dbus-server \
    dist-arm64/client/bin/test-client \
    dist-arm64/client/lib/libweaknet.so \
    dist-arm64/server/build/flow_rate.bpf.o \
    dist-arm64/server/build/a2dp_media.bpf.o
"

echo "===== 同步到开发板 $BOARD ====="

# rsync 增量同步，排除日志目录（保留开发板日志）
rsync -az --delete \
    --exclude 'server/logs/' \
    -e ssh \
    dist-arm64/ \
    "$BOARD:/home/radxa/weaknet/"

echo
echo "===== 部署完成 ====="
echo "目标: $BOARD:/home/radxa/weaknet/"
echo
echo "下一步: 运行测试"
echo "  ssh -t $BOARD 'sudo /home/radxa/weaknet-test-full.sh'"
```

添加执行权限：

```bash
chmod +x tools/ci.sh
```

### 4.5 开发板创建测试脚本

在开发板上创建一键测试脚本。

```bash
ssh radxa@192.168.2.77 'cat > /home/radxa/weaknet-test-full.sh' <<'REMOTE_EOF'
#!/usr/bin/env bash
set -euo pipefail

# ============================================================================
# WeakNet 开发板测试脚本
# 在私有 D-Bus 会话中启动服务端并运行客户端测试
# ============================================================================

export HOME=/home/radxa
export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
export LD_LIBRARY_PATH=/home/radxa/weaknet/lib:/home/radxa/weaknet/client/lib:/usr/local/lib

exec dbus-run-session -- bash -lc '
set -u

# 解除内存锁定限制（eBPF 需要）
ulimit -l unlimited 2>/dev/null || true

cd /home/radxa/weaknet/server
mkdir -p logs/server
: > /tmp/weaknet-server.log

echo "===== 启动服务端 ====="
./bin/weaknet-dbus-server \
    >/tmp/weaknet-server.log 2>&1 &

SERVER_PID=$!

cleanup() {
    kill "$SERVER_PID" 2>/dev/null || true
    wait "$SERVER_PID" 2>/dev/null || true
}
trap cleanup EXIT

# 等待服务端启动
echo "等待服务端启动 (15s)..."
sleep 15

if ! kill -0 "$SERVER_PID" 2>/dev/null; then
    echo "===== 服务端启动失败 ====="
    cat /tmp/weaknet-server.log
    exit 1
fi

echo "服务端运行中 (PID=$SERVER_PID)"

cd /home/radxa/weaknet

echo
echo "===== 客户端: get ====="
./client/bin/test-client get

echo
echo "===== 客户端: health ====="
./client/bin/test-client health

echo
echo "===== 项目 BPF 程序挂载情况 ====="
/usr/sbin/bpftool prog show 2>/dev/null | \
    grep -A4 -E "l2cap|sock_send|tcp_transmit|udp_send" || \
    echo "(未检测到项目 BPF 程序，可能需要 root 权限或 eBPF 加载失败)"

echo
echo "===== 服务端日志 (最后 80 行) ====="
tail -n 80 /tmp/weaknet-server.log

echo
echo "===== 测试完成 ====="
'
REMOTE_EOF

ssh radxa@192.168.2.77 'chmod +x /home/radxa/weaknet-test-full.sh'
```

验证脚本已创建：

```bash
ssh radxa@192.168.2.77 'ls -la /home/radxa/weaknet-test-full.sh'
# 预期: -rwxr-xr-x ... weaknet-test-full.sh
```

## 五、日常开发循环

配置完成后，日常开发只需三步。

### 步骤 1: 修改源码

在开发机上用 IDE 或 vim 修改源码：

```
server/src/*.cpp        # C++ 服务端源码
server/src/*.bpf.c      # eBPF 程序源码
server/include/*.hpp    # C++ 头文件
client/*.cpp            # 客户端源码
client/weaknet_client.h # 客户端头文件
```

### 步骤 2: 一键部署

```bash
cd ~/AI-powered-Network-Diagnostics
./tools/ci.sh
```

脚本会自动完成：

1. 检查并启动常驻容器
2. 在容器内增量编译（只重编变化的文件）
3. 整理 `dist-arm64/` 部署目录
4. `rsync` 差异同步到开发板（只传变化的文件）

预期输出：

```
===== 检查构建容器 =====
===== ARM64 增量编译 (并行度 -j1) =====
--- 编译服务端与 BPF 程序 ---
make: 进入目录'/src/server'
... (增量编译，只编译变化的文件)
make: 离开目录'/src/server'
--- 编译客户端库与测试程序 ---
...
===== 生成部署目录 =====
===== 架构检查 =====
dist-arm64/server/bin/weaknet-dbus-server: ELF 64-bit LSB pie executable, ARM aarch64, ...
dist-arm64/client/bin/test-client:         ELF 64-bit LSB pie executable, ARM aarch64, ...
...
===== 同步到开发板 radxa@192.168.2.77 =====
sending incremental file list
... (只传输变化的文件)

===== 部署完成 =====
目标: radxa@192.168.2.77:/home/radxa/weaknet/
```

### 步骤 3: 远程测试

```bash
ssh -t radxa@192.168.2.77 'sudo /home/radxa/weaknet-test-full.sh'
```

脚本会自动完成：

1. 启动私有 D-Bus 会话（`dbus-run-session`）
2. 启动 `weaknet-dbus-server`（等待 15 秒）
3. 运行 `test-client get` 获取网络信息
4. 运行 `test-client health` 健康检查
5. `bpftool prog show` 验证 eBPF 挂载
6. 输出服务端日志

## 六、何时需要重操作

日常修改 C++/BPF 源码时，**只需运行 `ci.sh`**，不涉及以下重操作。

| 触发条件 | 需要重做的操作 | 命令 | 频率 |
|----------|---------------|------|------|
| 修改 C++/BPF 源码 | 只跑 ci.sh | `./tools/ci.sh` | 日常 |
| 修改 Dockerfile 或依赖版本 | 重新构建镜像 | `docker build ...` | 极少 |
| 开发板内核或 BTF 变化 | 重新生成 vmlinux.h | `ssh ... 'bpftool btf dump ...'` | 极少 |
| 容器意外删除 | 重新创建容器 | `docker run ...` | 偶发 |
| 添加新的系统依赖 | 重新构建镜像 | `docker build ...` | 极少 |

## 七、故障排查

### 7.1 容器问题

#### 容器不存在

```
错误: 容器 weaknet-arm64-dev 不存在
```

**原因**：常驻容器未创建或被删除。

**解决**：按 [4.3 节](#43-创建常驻构建容器) 重新创建容器。

#### 容器架构错误

```
docker exec weaknet-arm64-dev uname -m
# 输出 x86_64 而非 aarch64
```

**原因**：创建容器时缺少 `--platform linux/arm64`。

**解决**：删除并重新创建容器：

```bash
docker rm -f weaknet-arm64-dev
# 重新执行 4.3 节的 docker run 命令
```

#### QEMU 未注册

```
Unable to find image '...' locally
docker: Error response from daemon: no matching manifest for linux/amd64
```

**原因**：Docker 未启用 multiarch 支持。

**解决**：

```bash
# 安装 qemu-user-static
docker run --rm --privileged multiarch/qemu-user-static --reset -p yes

# 验证
docker run --rm --platform linux/arm64 arm64v8/debian:11 uname -m
# 预期: aarch64
```

### 7.2 编译问题

#### vmlinux.h 缺失

```
Warning: /sys/kernel/btf/vmlinux not found, vmlinux.h not generated
fatal error: vmlinux.h: No such file or directory
```

**原因**：容器内没有开发机的 BTF，且 `board-assets/vmlinux.h` 未复制到 `server/build/`。

**解决**：`ci.sh` 已自动处理此问题。如果手动编译，需执行：

```bash
docker exec weaknet-arm64-dev bash -c \
    'mkdir -p /src/server/build && cp /src/board-assets/vmlinux.h /src/server/build/vmlinux.h'
```

#### cc1 崩溃（QEMU 并行度过高）

```
internal compiler error: Segmentation fault
```

**原因**：QEMU 模拟下 ARM64 GCC 并行度过高导致崩溃。

**解决**：必须使用 `-j1`，不要使用更高的并行度。Makefile 已配置 ccache，即使 `-j1` 编译，增量编译也只需要几秒。

#### libbpf 找不到

```
fatal error: bpf/bpf.h: No such file or directory
```

## 十、eBPF 部署详解

### eBPF 程序的本质

eBPF 程序是**平台无关的内核字节码**，运行在内核的 BPF 虚拟机中，不是直接跑在 ARM64 或 x86_64 CPU 上。这意味着：

```
开发机 (x86_64)                      开发板 (ARM64)
┌──────────────────┐                ┌──────────────────┐
│ .bpf.c 源码       │                │                  │
│      ↓           │                │  内核 BPF VM      │
│ clang -target bpf│                │  加载 .bpf.o 字节码│
│      ↓           │                │  (架构无关)        │
│ .bpf.o 字节码    │  rsync 传输    │                  │
│      ↓───────────── rsync ──────→ │  运行在内核中      │
│ 无需交叉编译!     │                │  与内核版本匹配即可 │
└──────────────────┘                └──────────────────┘
```

**关键结论**：`.bpf.o` 字节码不需要交叉编译，但**和目标内核版本相关**。

### 不同场景下的部署操作

| 场景 | 需要做什么 | 是否需要交叉编译 |
|------|-----------|-----------------|
| 只改了 `.bpf.c` 源码 | 重编译 `.bpf.o` + rsync 到板子 | ❌ 不需要 |
| 改了 `net_traffic.cpp` 等加载代码 | 交叉编译服务端 + rsync 二进制 + `.bpf.o` | ✅ 需要 |
| 开发板内核升级 | 从板子提取新 `vmlinux.h` + 重编译 `.bpf.o` | ❌ 不需要 |
| 只改了客户端/非 eBPF 代码 | 交叉编译客户端 + rsync | ✅ 需要 |

### 场景 1：只改了 eBPF 程序（最常见）

日常开发中，修改 eBPF 探针逻辑是最频繁的操作。此时**不需要重新交叉编译服务端二进制**。

```bash
# 1. 在开发机重新编译 .bpf.o（不需要交叉编译）
# .bpf.c → .bpf.o 是 clang -target bpf，与目标架构无关
cd server
make build/flow_rate.bpf.o   # 或其他 .bpf.o

# 2. 同步到开发板（只传字节码文件）
rsync -avz server/build/*.bpf.o radxa@board:/home/radxa/weaknet/server/build/

# 3. 重启服务端使其加载新 BPF 程序
ssh radxa@board 'sudo killall weaknet-dbus-server; sleep 2; sudo /home/radxa/weaknet-test-full.sh'
```

服务端在启动时通过 `bpf_object__open("build/flow_rate.bpf.o")` 加载 BPF 字节码，无需重新编译二进制。

### 场景 2：新增 eBPF 探针（如 DNS 监控）

新增一个 eBPF 程序需要同时修改 BPF 源码和用户态加载代码：

```
步骤 1: 写 .bpf.c 源码
         ↓
步骤 2: clang -target bpf 编译成 .bpf.o（开发机即可）
         ↓
步骤 3: 修改 net_traffic.cpp 添加加载逻辑（需要交叉编译）
         ↓
步骤 4: rsync .bpf.o + 新二进制到开发板
```

### 场景 3：开发板内核升级

eBPF 程序使用 CO-RE（Compile Once, Run Everywhere），依赖目标内核的 BTF 类型信息：

```bash
# 1. 在开发板上提取新的 vmlinux.h
ssh radxa@board \
    'bpftool btf dump file /sys/kernel/btf/vmlinux format c' \
    > board-assets/vmlinux.h

# 2. 在开发机重新编译所有 .bpf.o
cd server
make build/flow_rate.bpf.o
make build/a2dp_media.bpf.o
# 如果有新 BPF 程序也要一起编译

# 3. 同步到开发板
rsync -avz server/build/*.bpf.o radxa@board:/home/radxa/weaknet/server/build/
```

**何时会触发**：
- 开发板 `apt upgrade` 更新了内核
- 开发板刷了新系统镜像
- `uname -r` 输出的版本号发生变化

**验证方法**：
```bash
ssh radxa@board 'uname -r'                    # 查看内核版本
ssh radxa@board 'ls /sys/kernel/btf/vmlinux'  # 确认 BTF 存在
```

### 当前项目的 BPF 程序清单

（截至 2026-08-05，共 6 个）

| 文件 | 挂点 | 功能 | 部署路径 |
|------|------|------|---------|
| `server/src/flow_rate.bpf.c` | `kprobe/tcp_retransmit_skb` + `kprobe/ip_queue_xmit` + `kprobe/udp_sendmsg` | 每进程 TCP/UDP 流量 + 重传统计 | `server/build/flow_rate.bpf.o` |
| `server/src/tcp_retransmit.bpf.c` | `kprobe/tcp_retransmit_skb` + `kprobe/tcp_sendmsg` | TCP 连接级丢包率 | `server/build/tcp_retransmit.bpf.o` |
| `server/src/dns_monitor.bpf.c` | `kprobe/udp_sendmsg` + `kprobe/udp_recvmsg` | DNS 解析延迟/超时 | `server/build/dns_monitor.bpf.o` |
| `server/src/wifi_packet_loss.bpf.c` | `tracepoint/net/netif_receive_skb` + `net_dev_queue` + `net_dev_xmit` | Wi-Fi 收发丢包归因 | `server/build/wifi_packet_loss.bpf.o` |
| `server/src/http_latency.bpf.c` | `kprobe/tcp_sendmsg` + `kprobe/tcp_recvmsg` | HTTP 请求级 TTFB 延迟 | `server/build/http_latency.bpf.o` |
| `server/src/bpf/a2dp_media.bpf.c` | `kprobe/l2cap_sock_sendmsg` + `kprobe/__sock_sendmsg` | 蓝牙 A2DP 音频流量/卡顿 | `server/build/a2dp_media.bpf.o` |

> **注意**：`tcp_retransmit_skb` 探针被 `flow_rate.bpf.c` 和 `tcp_retransmit.bpf.c` 各自独立加载（双消费者），前者按进程聚合、后者按连接聚合，不做技术合并。

新增 BPF 程序时需要同步更新：
1. `server/Makefile` — 添加新的编译规则
2. `tools/ci.sh` — 添加新的 `.bpf.o` 到 dist-arm64 的复制
3. `weaknet-test-full.sh` — `bpftool prog show` 中添加新的过滤关键词
4. 对应监控器在 `server.cpp` 中新增启动线程（纳入 `ServerContext` 生命周期）

### 常见问题

#### eBPF 加载失败：`LIBBPF: prog 'xxx': BTF is required`

**原因**：目标内核没有 BTF 支持。

**解决**：
```bash
ssh radxa@board 'ls /sys/kernel/btf/vmlinux'
# 如果不存在，内核需要 CONFIG_DEBUG_INFO_BTF=y
```

#### eBPF 加载失败：`invalid func unknown#xxx`

**原因**：BPF 程序调用了目标内核不支持的 helper 函数。

**解决**：检查内核版本，某些 helper 函数（如 `bpf_get_socket_cookie`）需要 4.18+。

#### eBPF 加载成功但 Map 读取为空

**原因**：挂点函数名在新内核中被重命名或移除。

**解决**：
```bash
# 在开发板上检查函数是否存在
ssh radxa@board 'sudo bpftrace -l "kprobe:tcp_retransmit_skb"'
# 如果输出为空，说明该内核版本没有这个函数
```

## 十二、编译系统详解

### 编译架构

Makefile 采用**单文件独立编译 + ccache 缓存**架构：

```makefile
# 每个 .cpp 独立编译为 .o（ccache 单文件缓存生效）
$(BUILD_DIR)/%.o: src/%.cpp $(INC) | dirs
    $(CC) $(CXXFLAGS) $(INCLUDES) -Iinclude -c $< -o $@

# 最后链接
$(TARGET): $(OBJECTS)
    $(CC) -o $@ $^ $(LDFLAGS)
```

**关键设计**：
- 每个 `.cpp` 文件独立编译为 `.o`
- ccache 自动缓存编译结果
- 改动单个文件时，只有该文件重新编译，其余 31 个 `.o` 直接复用

### 编译性能

| 场景 | 耗时 | 说明 |
|------|------|------|
| 首次全量编译（冷缓存） | ~30 分钟 | QEMU 模拟，不可避免 |
| 改 1 个文件后增量编译 | **~2 秒** | ccache 命中，只重编 1 个 .o |
| 无改动重新编译 | ~0.7 秒 | make 检测到无变化，秒过 |

### 编译规则

**必须遵守**：

1. **使用 `-j1`**：QEMU ARM64 模拟下高并行度会导致编译器崩溃
2. **不要设置 timeout**：QEMU 编译较慢，设置 timeout 会导致编译中断
3. **保持容器运行**：容器是常驻的，避免每次重新创建的开销

```bash
# ✅ 正确方式
docker exec weaknet-arm64-dev bash -c 'cd /src && cmake --build build-arm64 -j1'

# ❌ 错误方式（会导致崩溃或超时）
docker exec weaknet-arm64-dev bash -c 'cd /src && cmake --build build-x86 -j2'
timeout 600 docker exec weaknet-arm64-dev bash -c 'cd /src && cmake --build build-arm64 -j1'
```

### ccache 缓存管理

容器内已安装 ccache，自动生效：

```bash
# 查看缓存统计
docker exec weaknet-arm64-dev ccache -s

# 清空缓存（重新开始）
docker exec weaknet-arm64-dev ccache --clear
```

### 编译产物验证

编译完成后验证架构：

```bash

file /src/server/bin/weaknet-dbus-server
# 预期: ELF 64-bit LSB pie executable, ARM aarch64
'
```

- ccache 透明集成

```

#### CMake 构建产物路径

| 产物 | CMake 路径 | Makefile 路径 |
|------|-----------|--------------|
| 服务端二进制 | `build-arm64/server/weaknet-dbus-server` | `server/bin/weaknet-dbus-server` |
| eBPF 程序 | `build-arm64/server/build/*.bpf.o` | `server/build/*.bpf.o` |
| 客户端库 | `build-arm64/client/lib/libweaknet.so` | `build-arm64/client/lib/libweaknet.so` |
| 测试二进制 | `build-x86/server/test/test_*` | `server/test/bin/test_*` |

> **注意**：CMake 和 Makefile 的构建产物路径不同，但最终都通过 `dist-arm64/` 统一打包部署。

#### CMake 手动编译部署

```bash
# 1. 容器内 CMake 编译
docker exec weaknet-arm64-dev bash -c '
cd /src
cmake -B build-arm64 -DCMAKE_BUILD_TYPE=Debug
cmake --build build-arm64 -j1
'

# 2. 打包部署目录
docker exec weaknet-arm64-dev bash -c '
cd /src
rm -rf dist-arm64
mkdir -p dist-arm64/server/bin dist-arm64/server/build \
         dist-arm64/client/bin dist-arm64/client/lib dist-arm64/lib

install -m 0755 build-arm64/server/weaknet-dbus-server dist-arm64/server/bin/
for f in build-arm64/server/build/*.bpf.o; do install -m 0644 "$f" dist-arm64/server/build/; done
install -m 0755 build-arm64/client/bin/test_client_bin dist-arm64/client/bin/test-client
install -m 0644 build-arm64/client/lib/libweaknet.so dist-arm64/client/lib/
cp -a /usr/local/lib/libbpf.so* dist-arm64/lib/
'

# 3. 部署到开发板
rsync -az --delete --exclude "server/logs/" -e ssh \
    dist-arm64/ radxa@192.168.2.77:/home/radxa/weaknet/

# 4. 运行测试
ssh -t radxa@192.168.2.77 'sudo /home/radxa/weaknet-test-full.sh'
```

### 部署注意事项

#### rsync --delete 权限问题

如果开发板上存在由 root 创建的旧目录（如 `logs/`、`server/server/log/`），普通用户 `radxa` 无法删除，会导致 `rsync --delete` 报 exit code 23。

**解决方案**：部署前先清理残留目录：

```bash
ssh radxa@192.168.2.77 'sudo rm -rf /home/radxa/weaknet/logs /home/radxa/weaknet/server/server'
```

或者在 `ci.sh` 中使用 `sudo` 清理（已支持）。

#### 首次部署

如果开发板上从未部署过，需要先创建测试脚本：

```bash
ssh radxa@192.168.2.77 'cat > /home/radxa/weaknet-test-full.sh' <<'REMOTE_EOF'
#!/usr/bin/env bash
set -euo pipefail

    cat /tmp/weaknet-server.log

echo "服务端运行中 (PID=$SERVER_PID)"
cd /home/radxa/weaknet
echo; echo "===== 客户端: get ====="
./client/bin/test-client get
echo; echo "===== 客户端: health ====="
./client/bin/test-client health
echo; echo "===== 项目 BPF 程序挂载情况 ====="

echo; echo "===== 服务端日志 (最后 80 行) ====="

### 历史数据查询工具

服务端内置 SQLite 历史数据持久化功能，每 5 分钟将当前网络状态写入数据库，保留 7 天。

#### 数据库位置

```
/tmp/weaknet/history.db   (root 权限运行时)
```

#### CLI 工具用法

```bash
# 查看数据库信息
sudo /home/radxa/weaknet/server/bin/history_query_tool --info

# 查询最近 1 小时的 wlan0 数据
sudo /home/radxa/weaknet/server/bin/history_query_tool --iface wlan0 --last 1h

# 查询所有网卡最近 30 分钟
sudo /home/radxa/weaknet/server/bin/history_query_tool --all --last 30m

# 指定时间范围查询
sudo /home/radxa/weaknet/server/bin/history_query_tool --iface wlan0 \
    --start "2026-08-20T00:00:00" --end "2026-08-20T06:00:00"

# 输出原始 JSON
sudo /home/radxa/weaknet/server/bin/history_query_tool --iface wlan0 --last 1h --json

# 清理超过 7 天的数据
sudo /home/radxa/weaknet/server/bin/history_query_tool --cleanup 7
```

#### 数据库 Schema

| 字段 | 类型 | 说明 |
|------|------|------|
| ts | TEXT | ISO 8601 时间戳 |
| iface | TEXT | 网卡名 |
| rtt_ms | INTEGER | RTT 延迟 (ms) |
| jitter_ms | REAL | 抖动 (ms) |
| rssi_dbm | INTEGER | Wi-Fi 信号强度 (dBm) |
| tcp_loss | REAL | TCP 丢包率 (%) |
| quality | TEXT | 质量等级 (GOOD/FAIR/POOR) |
| score | REAL | 质量评分 |
| traffic_bps | INTEGER | 流量 (bytes/s) |
| traffic_pps | INTEGER | 包速率 (packets/s) |
| flows | INTEGER | 活跃连接数 |

#### D-Bus 查询方法

```bash
# 通过 D-Bus 查询历史数据（需在同一会话内）
dbus-send --session --dest=com.example.WeakNet \
    --type=method_call --print-reply \
    /com/example/WeakNet \
    com.example.WeakNet:GetHistory \
    string:"wlan0" string:"" string:"" int32:100
```
