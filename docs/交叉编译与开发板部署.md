# 交叉编译与开发板部署指南

## 一、概述

本文档描述如何将 WeakNet 网络诊断系统从 x86_64 开发机交叉编译到 ARM64 开发板（Radxa Cubie A7A），并建立高效的日常开发循环。

### 核心思路

> **电脑编辑源码 → 常驻 ARM64 构建容器做增量编译 → `rsync` 只同步变化的产物 → 开发板运行测试。**

相比传统的"全量编译 + 整包 scp"方式，本方案将日常操作压缩为一条命令：

```bash
./tools/dev-deploy.sh
```

### 方案优势

| 传统方式 | 本方案 |
|----------|--------|
| 每次重建 Docker 镜像 | 镜像只构建一次 |
| `make clean` 全量编译 | 增量编译，只重编变化文件 |
| 重新打 tar 包 | 直接整理部署目录 |
| 每次手动 scp 整包 | `rsync` 只传差异文件 |
| 重新生成 vmlinux.h | 预置开发板 vmlinux.h |

## 二、架构与原理

### 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│  开发机 (x86_64 CentOS Stream 10)                           │
│                                                             │
│  ┌─────────────┐    bind mount     ┌──────────────────┐    │
│  │  源码编辑    │ ───────────────→ │ weaknet-arm64-dev│    │
│  │  (IDE/vim)  │   /home/.../src   │ (常驻ARM64容器)   │    │
│  └─────────────┘                   │                  │    │
│                                    │ • 增量 make -j2  │    │
│                                    │ • 生成 dist-arm64│    │
│                                    └────────┬─────────┘    │
│                                             │              │
│                                             │ rsync 增量   │
└─────────────────────────────────────────────┼──────────────┘
                                              │
                                              ↓
┌─────────────────────────────────────────────────────────────┐
│  开发板 (ARM64 Radxa Cubie A7A)                             │
│  /home/radxa/weaknet/                                       │
│  ├── server/bin/weaknet-dbus-server                         │
│  ├── server/build/*.bpf.o                                   │
│  ├── client/bin/test-client                                 │
│  ├── client/lib/libweaknet.so                               │
│  └── lib/libbpf.so*                                         │
│                                                             │
│  weaknet-test.sh  ← SSH 远程执行                             │
└─────────────────────────────────────────────────────────────┘
```

### 关键设计

| 设计 | 作用 |
|------|------|
| **bind mount 源码** | 电脑改源码，容器立即看到，无需复制源码 |
| **常驻容器** | 避免每次 `docker run` 开销，保留编译缓存 |
| **不 make clean** | 只重编变化文件，实现增量编译 |
| **rsync --delete** | 只传差异文件，自动清理开发板多余文件 |
| **vmlinux.h 预置** | 从 board-assets 复制，不依赖容器内生成 |
| **dbus-run-session** | 开发板无需系统 D-Bus 服务，私有会话即可测试 |

### 构建产物映射

项目有两个 Makefile，分别负责不同产物：

| 构建命令 | 产物 | 路径 |
|----------|------|------|
| `make -C server -j2` | 服务端可执行文件 | `server/bin/weaknet-dbus-server` |
| `make -C server -j2` | 流量监控 BPF 程序 | `server/build/flow_rate.bpf.o` |
| `make -C server -j2` | 蓝牙音频 BPF 程序 | `server/build/a2dp_media.bpf.o` |
| `make client-lib -j2` | 客户端动态库 | `client/lib/libweaknet.so` |
| `make client-lib -j2` | 客户端测试程序 | `client/bin/test-client` |

## 四、一次性配置

以下步骤只需执行一次，配置完成后长期有效。

### 4.1 构建 ARM64 镜像

镜像基于 Debian 11，包含交叉编译所需的全套工具链和 libbpf v1.3.0。

Dockerfile 位于 [.docker/arm64-builder/Dockerfile](file:///home/tanqf/AI-powered-Network-Diagnostics/.docker/arm64-builder/Dockerfile)。

```bash
cd ~/AI-powered-Network-Diagnostics

# 构建 ARM64 镜像（使用 QEMU 模拟，首次较慢）
docker build \
    --platform linux/arm64 \
    -f .docker/arm64-builder/Dockerfile \
    -t weaknet-builder:bullseye-arm64 \
    .
```

验证镜像：

```bash
docker images weaknet-builder:bullseye-arm64
# 预期: weaknet-builder  bullseye-arm64  ...  963MB

docker run --rm --platform linux/arm64 weaknet-builder:bullseye-arm64 uname -m
# 预期: aarch64
```

> **说明**：此步骤已完成，镜像 `weaknet-builder:bullseye-arm64`（963MB）已存在。除非修改 Dockerfile 或依赖版本，否则无需重新构建。

### 4.2 准备开发板 vmlinux.h

eBPF 程序编译需要目标内核的 BTF 类型信息。开发板的内核与开发机不同，必须使用开发板的 `vmlinux.h`。

```bash
# 1. 在开发板上生成 vmlinux.h
ssh radxa@192.168.2.77 \
    'bpftool btf dump file /sys/kernel/btf/vmlinux format c' \
    > board-assets/vmlinux.h

# 2. 验证文件
ls -lh board-assets/vmlinux.h
# 预期: 约 2.4MB

head -5 board-assets/vmlinux.h
# 预期: #ifndef __VMLINUX_H__
#       #define __VMLINUX_H__
```

> **说明**：此步骤已完成，[board-assets/vmlinux.h](file:///home/tanqf/AI-powered-Network-Diagnostics/board-assets/vmlinux.h)（2.4MB）已就位。除非开发板内核发生变化，否则无需重新生成。

### 4.3 创建常驻构建容器

创建一个长期运行的 ARM64 容器，通过 bind mount 共享源码目录。

```bash
cd ~/AI-powered-Network-Diagnostics

# 删除可能存在的旧容器
docker rm -f weaknet-arm64-dev 2>/dev/null || true

# 创建常驻容器
docker run -d \
    --name weaknet-arm64-dev \
    --platform linux/arm64 \
    --user "$(id -u):$(id -g)" \
    -e HOME=/tmp \
    -v "$PWD":/src:Z \
    -w /src \
    weaknet-builder:bullseye-arm64 \
    sleep infinity
```

参数说明：

| 参数 | 作用 |
|------|------|
| `--platform linux/arm64` | 以 ARM64 架构运行（QEMU 模拟） |
| `--user $(id -u):$(id -g)` | 使用当前用户身份，避免文件权限问题 |
| `-e HOME=/tmp` | 设置 HOME 目录（避免权限警告） |
| `-v "$PWD":/src:Z` | bind mount 源码目录，`:Z` 处理 SELinux 标签 |
| `-w /src` | 设置工作目录 |
| `sleep infinity` | 保持容器常驻运行 |

验证容器：

```bash
# 检查容器状态
docker ps --filter name=weaknet-arm64-dev
# 预期: STATUS = Up ...

# 验证架构
docker exec weaknet-arm64-dev uname -m
# 预期: aarch64

# 验证源码可见
docker exec weaknet-arm64-dev ls /src/server/Makefile
# 预期: /src/server/Makefile
```

### 4.4 创建一键部署脚本

在开发机创建增量编译与部署脚本。

```bash
cd ~/AI-powered-Network-Diagnostics
mkdir -p tools
```

创建 [tools/dev-deploy.sh](file:///home/tanqf/AI-powered-Network-Diagnostics/tools/dev-deploy.sh)：

```bash
#!/usr/bin/env bash
set -euo pipefail

# ============================================================================
# WeakNet 增量编译与部署脚本
# 用法: ./tools/dev-deploy.sh
# 环境:
#   CONTAINER - 构建容器名 (默认: weaknet-arm64-dev)
#   BOARD     - 开发板 SSH 地址 (默认: radxa@192.168.2.77)
#   JOBS      - 编译并行度 (默认: 2)
# ============================================================================

CONTAINER="${CONTAINER:-weaknet-arm64-dev}"
BOARD="${BOARD:-radxa@192.168.2.77}"
JOBS="${JOBS:-2}"

ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
cd "$ROOT"

echo "===== 检查构建容器 ====="

if ! docker inspect "$CONTAINER" >/dev/null 2>&1; then
    echo "错误: 容器 $CONTAINER 不存在"
    echo "请先按文档创建常驻 ARM64 构建容器"
    exit 1
fi

if [ "$(docker inspect -f '{{.State.Running}}' "$CONTAINER")" != "true" ]; then
    echo "启动容器 $CONTAINER ..."
    docker start "$CONTAINER" >/dev/null
fi

echo "===== ARM64 增量编译 (并行度 -j${JOBS}) ====="

docker exec "$CONTAINER" bash -lc "
set -euo pipefail
cd /src

# vmlinux.h 仅在内核改变时才需要更新，这里从 board-assets 复制
mkdir -p server/build
cp board-assets/vmlinux.h server/build/vmlinux.h

# 不执行 make clean，只重新编译发生变化的文件
echo '--- 编译服务端与 BPF 程序 ---'
make -C server -j${JOBS}

echo '--- 编译客户端库与测试程序 ---'
make client-lib -j${JOBS}

echo '===== 生成部署目录 ====='

rm -rf dist-arm64

mkdir -p \
    dist-arm64/server/bin \
    dist-arm64/server/build \
    dist-arm64/server/logs/server \
    dist-arm64/client/bin \
    dist-arm64/client/lib \
    dist-arm64/lib

# 服务端
install -m 0755 \
    server/bin/weaknet-dbus-server \
    dist-arm64/server/bin/weaknet-dbus-server

# BPF 程序
install -m 0644 \
    server/build/flow_rate.bpf.o \
    dist-arm64/server/build/flow_rate.bpf.o

install -m 0644 \
    server/build/a2dp_media.bpf.o \
    dist-arm64/server/build/a2dp_media.bpf.o

# 客户端
install -m 0755 \
    client/bin/test-client \
    dist-arm64/client/bin/test-client

install -m 0644 \
    client/lib/libweaknet.so \
    dist-arm64/client/lib/libweaknet.so

# libbpf 运行时依赖（开发板可能未安装 libbpf 1.3.0）
cp -a /usr/local/lib/libbpf.so* dist-arm64/lib/

echo '===== 架构检查 ====='

file \
    dist-arm64/server/bin/weaknet-dbus-server \
    dist-arm64/client/bin/test-client \
    dist-arm64/client/lib/libweaknet.so \
    dist-arm64/server/build/flow_rate.bpf.o \
    dist-arm64/server/build/a2dp_media.bpf.o
"

echo "===== 同步到开发板 $BOARD ====="

# rsync 增量同步，排除日志目录（保留开发板日志）
rsync -az --delete \
    --exclude 'server/logs/' \
    -e ssh \
    dist-arm64/ \
    "$BOARD:/home/radxa/weaknet/"

echo
echo "===== 部署完成 ====="
echo "目标: $BOARD:/home/radxa/weaknet/"
echo
echo "下一步: 运行测试"
echo "  ssh -t $BOARD 'sudo /home/radxa/weaknet-test.sh'"
```

添加执行权限：

```bash
chmod +x tools/dev-deploy.sh
```

### 4.5 开发板创建测试脚本

在开发板上创建一键测试脚本。

```bash
ssh radxa@192.168.2.77 'cat > /home/radxa/weaknet-test.sh' <<'REMOTE_EOF'
#!/usr/bin/env bash
set -euo pipefail

# ============================================================================
# WeakNet 开发板测试脚本
# 在私有 D-Bus 会话中启动服务端并运行客户端测试
# ============================================================================

export HOME=/home/radxa
export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
export LD_LIBRARY_PATH=/home/radxa/weaknet/lib:/home/radxa/weaknet/client/lib:/usr/local/lib

exec dbus-run-session -- bash -lc '
set -u

# 解除内存锁定限制（eBPF 需要）
ulimit -l unlimited 2>/dev/null || true

cd /home/radxa/weaknet/server
mkdir -p logs/server
: > /tmp/weaknet-server.log

echo "===== 启动服务端 ====="
./bin/weaknet-dbus-server \
    >/tmp/weaknet-server.log 2>&1 &

SERVER_PID=$!

cleanup() {
    kill "$SERVER_PID" 2>/dev/null || true
    wait "$SERVER_PID" 2>/dev/null || true
}
trap cleanup EXIT

# 等待服务端启动
echo "等待服务端启动 (15s)..."
sleep 15

if ! kill -0 "$SERVER_PID" 2>/dev/null; then
    echo "===== 服务端启动失败 ====="
    cat /tmp/weaknet-server.log
    exit 1
fi

echo "服务端运行中 (PID=$SERVER_PID)"

cd /home/radxa/weaknet

echo
echo "===== 客户端: get ====="
./client/bin/test-client get

echo
echo "===== 客户端: health ====="
./client/bin/test-client health

echo
echo "===== 项目 BPF 程序挂载情况 ====="
/usr/sbin/bpftool prog show 2>/dev/null | \
    grep -A4 -E "l2cap|sock_send|tcp_transmit|udp_send" || \
    echo "(未检测到项目 BPF 程序，可能需要 root 权限或 eBPF 加载失败)"

echo
echo "===== 服务端日志 (最后 80 行) ====="
tail -n 80 /tmp/weaknet-server.log

echo
echo "===== 测试完成 ====="
'
REMOTE_EOF

ssh radxa@192.168.2.77 'chmod +x /home/radxa/weaknet-test.sh'
```

验证脚本已创建：

```bash
ssh radxa@192.168.2.77 'ls -la /home/radxa/weaknet-test.sh'
# 预期: -rwxr-xr-x ... weaknet-test.sh
```

## 五、日常开发循环

配置完成后，日常开发只需三步。

### 步骤 1: 修改源码

在开发机上用 IDE 或 vim 修改源码：

```
server/src/*.cpp        # C++ 服务端源码
server/src/*.bpf.c      # eBPF 程序源码
server/include/*.hpp    # C++ 头文件
client/*.cpp            # 客户端源码
client/weaknet_client.h # 客户端头文件
```

### 步骤 2: 一键部署

```bash
cd ~/AI-powered-Network-Diagnostics
./tools/dev-deploy.sh
```

脚本会自动完成：

1. 检查并启动常驻容器
2. 在容器内增量编译（只重编变化的文件）
3. 整理 `dist-arm64/` 部署目录
4. `rsync` 差异同步到开发板（只传变化的文件）

预期输出：

```
===== 检查构建容器 =====
===== ARM64 增量编译 (并行度 -j2) =====
--- 编译服务端与 BPF 程序 ---
make: 进入目录'/src/server'
... (增量编译，只编译变化的文件)
make: 离开目录'/src/server'
--- 编译客户端库与测试程序 ---
...
===== 生成部署目录 =====
===== 架构检查 =====
dist-arm64/server/bin/weaknet-dbus-server: ELF 64-bit LSB pie executable, ARM aarch64, ...
dist-arm64/client/bin/test-client:         ELF 64-bit LSB pie executable, ARM aarch64, ...
...
===== 同步到开发板 radxa@192.168.2.77 =====
sending incremental file list
... (只传输变化的文件)

===== 部署完成 =====
目标: radxa@192.168.2.77:/home/radxa/weaknet/
```

### 步骤 3: 远程测试

```bash
ssh -t radxa@192.168.2.77 'sudo /home/radxa/weaknet-test.sh'
```

脚本会自动完成：

1. 启动私有 D-Bus 会话（`dbus-run-session`）
2. 启动 `weaknet-dbus-server`（等待 15 秒）
3. 运行 `test-client get` 获取网络信息
4. 运行 `test-client health` 健康检查
5. `bpftool prog show` 验证 eBPF 挂载
6. 输出服务端日志

### 可选: 自定义环境变量

```bash
# 使用不同的开发板地址

# 提高并行度（稳定后可尝试）

# 使用不同的容器名

```

## 六、何时需要重操作

日常修改 C++/BPF 源码时，**只需运行 `dev-deploy.sh`**，不涉及以下重操作。

| 触发条件 | 需要重做的操作 | 命令 | 频率 |
|----------|---------------|------|------|
| 修改 C++/BPF 源码 | 只跑 dev-deploy.sh | `./tools/dev-deploy.sh` | 日常 |
| 修改 Dockerfile 或依赖版本 | 重新构建镜像 | `docker build ...` | 极少 |
| 开发板内核或 BTF 变化 | 重新生成 vmlinux.h | `ssh ... 'bpftool btf dump ...'` | 极少 |
| 容器意外删除 | 重新创建容器 | `docker run ...` | 偶发 |
| 添加新的系统依赖 | 重新构建镜像 | `docker build ...` | 极少 |

### 内核变更后更新 vmlinux.h

```bash
ssh radxa@192.168.2.77 \
    'bpftool btf dump file /sys/kernel/btf/vmlinux format c' \
    > board-assets/vmlinux.h
```

### 容器被删除后重建

## 七、故障排查

### 7.1 容器问题

#### 容器不存在

```
错误: 容器 weaknet-arm64-dev 不存在
```

**原因**：常驻容器未创建或被删除。

**解决**：按 [4.3 节](#43-创建常驻构建容器) 重新创建容器。

#### 容器架构错误

```
docker exec weaknet-arm64-dev uname -m
# 输出 x86_64 而非 aarch64
```

**原因**：创建容器时缺少 `--platform linux/arm64`。

**解决**：删除并重新创建容器：

```bash
docker rm -f weaknet-arm64-dev
# 重新执行 4.3 节的 docker run 命令
```

#### QEMU 未注册

```
Unable to find image '...' locally
docker: Error response from daemon: no matching manifest for linux/amd64
```

**原因**：Docker 未启用 multiarch 支持。

**解决**：

```bash
# 安装 qemu-user-static
docker run --rm --privileged multiarch/qemu-user-static --reset -p yes

# 验证
docker run --rm --platform linux/arm64 arm64v8/debian:11 uname -m
# 预期: aarch64
```

### 7.2 编译问题

#### vmlinux.h 缺失

```
Warning: /sys/kernel/btf/vmlinux not found, vmlinux.h not generated
fatal error: vmlinux.h: No such file or directory
```

**原因**：容器内没有开发机的 BTF，且 `board-assets/vmlinux.h` 未复制到 `server/build/`。

**解决**：`dev-deploy.sh` 已自动处理此问题。如果手动编译，需执行：

```bash
docker exec weaknet-arm64-dev bash -c \
    'mkdir -p /src/server/build && cp /src/board-assets/vmlinux.h /src/server/build/vmlinux.h'
```

#### cc1 崩溃（QEMU 并行度过高）

```
internal compiler error: Segmentation fault
```

**原因**：QEMU 模拟下 ARM64 GCC 并行度过高导致崩溃。

**解决**：降低并行度：

```bash
JOBS=1 ./tools/dev-deploy.sh
```

> **建议**：首次编译使用 `-j1`，稳定后尝试 `-j2`。不要直接使用 `-j8` 或更高。

#### libbpf 找不到

```
fatal error: bpf/bpf.h: No such file or directory
```

**原因**：镜像中 libbpf 未正确安装。

**解决**：重新构建镜像，确认 Dockerfile 中 libbpf 编译步骤正确：

```bash
docker build --no-cache \
    --platform linux/arm64 \
    -f .docker/arm64-builder/Dockerfile \
    -t weaknet-builder:bullseye-arm64 \
    .
```

### 7.3 部署问题

#### rsync 连接失败


```bash
# 1. 检查网络连通性
```

#### rsync 权限错误

```
rsync: mkstemp "/home/radxa/weaknet/..." failed: Permission denied
```

**原因**：开发板目标目录权限不足。

**解决**：

```bash
ssh radxa@192.168.2.77 'mkdir -p /home/radxa/weaknet && chmod 755 /home/radxa/weaknet'
```

#### 文件架构错误

```
dist-arm64/server/bin/weaknet-dbus-server: ELF 64-bit LSB ... x86-64
```

**原因**：编译产物是 x86_64 而非 ARM64，说明未在 ARM64 容器内编译。

**解决**：确认 `dev-deploy.sh` 通过 `docker exec` 在容器内编译，而非直接在开发机编译。

#### 服务端启动失败

```
===== 服务端启动失败 =====
```

常见原因：

| 错误信息 | 原因 | 解决 |
|----------|------|------|
| `error while loading shared libraries: libbpf.so.1` | libbpf 未找到 | 确认 `lib/libbpf.so*` 已同步，检查 `LD_LIBRARY_PATH` |

| `BPF objects not found` | BPF 文件缺失 | 确认 `server/build/*.bpf.o` 已同步 |

## 八、性能优化建议

### 编译提速

| 优化项 | 说明 | 风险 |
|--------|------|------|
| `-j2` 并行 | 稳定后从 `-j1` 升级到 `-j2` | 低（QEMU 下建议不超过 2） |
| ccache 缓存 | 容器内安装 ccache，加速重复编译 | 低 |
| 增量编译 | 不执行 `make clean`，保留 `.o` 文件 | 无 |

> **警告**：QEMU 模拟下 ARM64 GCC 在高并行度时可能崩溃（`cc1` 段错误）。建议不超过 `-j2`。

### 传输提速

| 优化项 | 说明 |
|--------|------|
| `rsync -z` | 压缩传输（已启用） |
| `rsync --delete` | 自动清理多余文件（已启用） |
| 排除日志 | `--exclude 'server/logs/'` 保留开发板日志（已启用） |

### 容器管理

```bash
# 查看容器资源占用
docker stats weaknet-arm64-dev --no-stream

# 停止容器（释放内存）
docker stop weaknet-arm64-dev

# 启动容器（下次编译前会自动启动）
docker start weaknet-arm64-dev

# 查看容器日志
docker logs weaknet-arm64-dev
```

## 十、总结

本方案将交叉编译部署流程分为两层：

1. **一次性配置**：构建镜像、准备 vmlinux.h、创建常驻容器、创建脚本
2. **日常循环**：改源码 → `dev-deploy.sh` → SSH 测试

日常开发中，一次小修改通常只需重新编译一两个文件，并传输几百 KB 的差异产物，大幅提升开发效率。

```
电脑源码是唯一源代码
        ↓
常驻 ARM64 容器增量编译
        ↓
rsync 差异部署
        ↓
SSH 一键测试
```
