# 双视角渲染：同一份骨架的两次投影

## 核心原则

**事实只有一份，投影有两份。**

准备两套说法的人，在被交叉追问时会出现前后矛盾——因为两套稿子是分别写的，细节对不上。正确做法是先有骨架，再从骨架渲染出两个视角。

判定标准：把外行版和行家版并排放，**每一条事实陈述必须互相兼容**。允许详略不同，不允许结论相反。

---

## 外行版（面试官不了解这个项目，甚至不熟这个领域）

### 目标

让对方在三十秒内理解「这件事解决了什么问题」，并且**不因为听不懂术语而失去兴趣**。

### 结构

1. **开场一句**：从收益或痛点说，不从技术名词说。
2. **三个要点**：每点一句，允许类比，允许省略实现。
3. **收尾一句**：落回「所以它能解决什么实际问题」。

### 写法规则

| 规则 | 说明 |
| :--- | :--- |
| 先问题后方案 | "监控程序自己很吃资源，就没法监控算力本来就紧的设备" —— 而不是"我们用了 eBPF" |
| 一个类比最多一处 | 类比是拐杖，拄两根就成了表演 |
| 术语要么不用，要么一句话解释 | 用错比不用更糟 |
| 不报数字 | 外行场景下数字没有参照系，且容易诱发追问 |
| 不主动提边界 | 外行版不需要防御，边界留到行家版 |

### 反例

> ❌ "我们基于 libbpf 和 CO-RE 实现了多探针采集，通过 BTF 重定位消除了布局依赖。"

问题：三个术语，零信息。对方只能点头。

> ✅ "监控系统本身如果很吃资源，就没法装在一台本来就算力紧张的设备上。所以我们把统计工作搬进操作系统内核里做，数据不用搬出来就把账算完了。"

---

## 行家版（面试官技术栈对口）

### 目标

让对方确认**你做过决策**，而不是照着教程搭了一遍。行家不听你复述原理，他听取舍。

### 结构

1. **开场一句**：直接给结论 + 选型。
2. **取舍 2~3 个**：每个都是「为什么是 X 不是 Y」。
3. **边界一句**：主动交出一个不成立的条件。
4. **收尾一句**：指向证据或验证方式。

### 写法规则

| 规则 | 说明 |
| :--- | :--- |
| 主动交边界 | 先说"这在 X 情况下不成立"，比被问出来强十倍 |
| 承认代价 | 答"没有代价"即判负 |
| 不铺陈背景 | 行家已知背景，铺陈只会显得在拖时间 |
| 数字只在有实测时出现 | 没有就说没有，并给出该测什么 |
| 收尾指向证据 | 说出可查的工具、指标或日志，这是可信度的锚 |

### 反例

> ❌ "我们用的 CO-RE，它通过 BTF 在加载时重定位，所以可以跨内核版本。"

问题：正确但是教科书内容，行家听完没有任何新信息。

> ✅ "结构体布局这块用的是 CO-RE，编译期只记类型名和成员名，加载时按目标机 BTF 重算偏移。好处是失效是显式的——字段改名了直接加载失败，不会静默读错内存。但它的前提是目标内核要有 BTF，而且模块化的结构体不在主 BTF 里，那部分得退回手工取偏移。"

---

## 两版对照检查表

渲染完成后逐条自检：

- [ ] 两版的核心事实一致，无互相矛盾的陈述
- [ ] 外行版没有未解释的术语
- [ ] 行家版至少有 2 个真实取舍
- [ ] 行家版有 1 个主动交出的边界
- [ ] 两版都没出现未实测的数字
- [ ] 外行版开场第一句不含技术名词
- [ ] 行家版开场第一句不解释基础概念

---

## 英文场景

用户说明有英文面试时，只补英文开场句（两版各一句），不重写全文。

开场句式参考：

- 外行版：`Monitoring that itself consumes significant resources can't be deployed on a device that's already resource-constrained — so we moved the accounting into the kernel, where the data never has to leave.`
- 行家版：`We used CO-RE: the compiler records type and member names, and offsets are resolved against the target kernel's BTF at load time — so a schema change fails loudly at load rather than silently reading the wrong memory.`
